# اطلاعات محصول (Product Documentation)

> تصمیم‌های مربوط به خود فروشگاه: نقش‌ها، مدل محصول، دسته‌بندی، قوانین کسب‌وکار و صفحات.
> شماره‌های `Q..` به سؤال‌های چت اصلی اشاره دارند (جدول کامل در `06-decision-log.md`).

## ۱. هدف پروژه

یک پروژه Full-Stack تمرینی برای **فروشگاه لوازم خانگی**:

- در ابتدا **۸ محصول** دارد.
- ادمین می‌تواند محصول اضافه، ویرایش و حذف کند.
- یک **Landing Page** دارد که محصولات در آن نمایش داده می‌شوند.
- روش کار: کدها فایل‌به‌فایل در VS Code کپی می‌شوند تا تسلط کامل روی پروژه ایجاد شود.

فعلاً **خرید، سبد خرید و پرداخت وجود ندارد.**

## ۲. نقش‌ها (Q1, Q7)

| نقش | امکانات |
|---|---|
| **Customer (مشتری)** | دیدن محصولات در Landing Page و صفحه جزئیات محصول |
| **Admin (ادمین)** | ورود به پنل، CRUD محصولات، CRUD دسته‌بندی‌ها |

- **انتخاب Q1:** گزینه B (مشتری + ادمین، بدون خرید)
- **انتخاب Q7:** فقط **یک ادمین ثابت**؛ موجودیت `User` و سیستم چندکاربره ساخته نمی‌شود.

## ۳. مدل محصول (Product)

| فیلد | توضیح / قانون |
|---|---|
| `id` | شناسه یکتای محصول (مرجع اصلی شناسایی) |
| `name` | اجباری، حداقل ۲ کاراکتر، **یکتا نیست** (Q31) |
| `description` | اجباری |
| `price` | عدد صحیح، به **تومان**، بزرگ‌تر از ۰ (Q16) |
| `image_url` | آدرس تصویر آپلودشده (فایل در دیتابیس ذخیره نمی‌شود) |
| `category_id` | اجباری، باید به یک Category موجود اشاره کند |
| `stock` | عدد صحیح، ۰ یا بیشتر |
| `sort_order` | عدد صحیح، ۰ یا بیشتر؛ ترتیب نمایش در Landing Page (Q25) |
| `is_active` | وضعیت فعال/غیرفعال برای Soft Delete (Q9) |

- **انتخاب Q2:** گزینه A، یعنی فیلدهای `id, name, description, price, image_url, category, stock`
- **انتخاب Q36:** فیلدهای `created_at` و `updated_at` **نداریم** (گزینه B). مدل ساده می‌ماند.

### قوانین اعتبارسنجی (Q33 — گزینه A)

```
name         → required, min 2 chars
description  → required
price        → integer > 0
stock        → integer >= 0
category_id  → required + must exist
sort_order   → integer >= 0
```

اعتبارسنجی هم در Frontend و هم در Backend انجام می‌شود؛ **Backend مرجع نهایی** است.

## ۴. مدل دسته‌بندی (Category) (Q3)

انتخاب گزینه B: Category یک **موجودیت مستقل** است و ادمین می‌تواند آن را مدیریت کند.

| فیلد | توضیح / قانون |
|---|---|
| `id` | شناسه |

رابطه: `Category 1 ─── N Product`

## ۵. قوانین کسب‌وکار (Business Rules)

### حذف محصول — Soft Delete + Restore (Q9, Q24)
- حذف محصول واقعی نیست؛ `is_active = false` می‌شود.
- ادمین می‌تواند محصول غیرفعال را **Restore** کند (`is_active = true`).
- مشتری فقط محصولات فعال را می‌بیند (Q23).
- پنل ادمین **همه محصولات** (فعال و غیرفعال) را با نمایش وضعیت می‌بیند (Q28).

### محصول غیرفعال و URL مستقیم (Q29)
اگر مشتری آدرس محصولِ غیرفعال را مستقیم باز کند، **404 Not Found** برمی‌گردد و این پیام فارسی نمایش داده می‌شود:

> محصول موردنظر پیدا نشد یا دیگر در فروشگاه فعال نیست.

این رفتار فقط برای Public API / Frontend است؛ ادمین همچنان محصول غیرفعال را می‌بیند و می‌تواند Restore کند.

### حذف دسته‌بندی (Q15, Q30)
- اگر Category **محصول داشته باشد، حذفش ممنوع** است.
- اگر محصولی نداشته باشد، **حذف واقعی (Hard Delete)** می‌شود.
- قانون کلی: `Product → Soft Delete + Restore` و `Category → Hard Delete`

### موجودی (Q12)
- `stock > 0` → محصول «موجود»
- `stock = 0` → محصول «ناموجود»؛ **همچنان در Landing Page نمایش داده می‌شود**

### تصویر محصول (Q10, Q11, Q34, Q35, Q37)
- تصویر **آپلود** می‌شود (نه لینک خارجی) و روی **Local Storage** سرور ذخیره می‌شود (مثلاً `/uploads/products/...`).
- در ساخت محصول، **تصویر اجباری** است.
- در ویرایش، تصویر اختیاری است: اگر تصویر جدید ارسال نشود، تصویر قبلی حفظ می‌شود.
- هنگام جایگزینی تصویر: **ابتدا تصویر جدید ذخیره می‌شود، سپس فایل قبلی حذف می‌شود** (تا اگر آپلود شکست خورد، تصویر قبلی از دست نرود).
- فایل تصویر داخل PostgreSQL ذخیره نمی‌شود؛ فقط `image_url` در دیتابیس می‌ماند.
- ذخیره‌سازی در نسخه اول Local است؛ انتقال به Object Storage (مثل S3) برای بعد در نظر گرفته شده.

### داده اولیه (Q26, Q27)
با یک **Seed** هنگام راه‌اندازی اولیه ساخته می‌شود:

```
Seed
 ├── Categories
 ├── 8 Products
 └── 1 Admin
```

بعد از آن، تغییرات فقط از طریق پنل ادمین انجام می‌شود.

## ۶. صفحات سمت مشتری (Q4, Q13, Q25, Q32)

```
/
├── Landing Page      → نمایش همه محصولات فعال (Product Cards)
└── /products/:id     → صفحه جزئیات محصول
```

- **Landing Page عمداً ساده است:** فقط نمایش محصولات؛ **بدون Search و بدون فیلتر دسته‌بندی** (Q13 — گزینه A).
- ترتیب نمایش: `ORDER BY sort_order ASC` روی محصولات فعال (Q25 — گزینه B).
- آدرس صفحه محصول با **id** است، نه slug (Q32 — گزینه A).
- صفحه جزئیات: عکس، نام، توضیحات، قیمت، دسته‌بندی و موجودی.

## ۷. صفحات پنل ادمین (Q5 — گزینه A)

```
/admin
├── Products
│   ├── List
│   ├── Add
│   ├── Edit
│   └── Delete
│
└── Categories
    ├── List
    ├── Add
    ├── Edit
    └── Delete
```

برای دسترسی به `/admin` ورود (Login) لازم است؛ جزئیات در `03-auth-and-security.md`.
